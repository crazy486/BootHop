# BootHop Implementation Plan

> **For agentic workers:** REQUIRED SUB-SKILL: Use superpowers:subagent-driven-development (recommended) or superpowers:executing-plans to implement this plan task-by-task. Steps use checkbox (`- [ ]`) syntax for tracking.

**Goal:** 实现经过批准的 BootHop 小型双系统一次性切换工具，并提供隔离的自动化测试和显式验收流程。

**Architecture:** Rust core 统一解析、identity、业务状态和错误；平台层封装固件、受保护记录、授权及重启。普通权限 Slint GUI 仅发送意图，按需提权 helper 独立验证并执行 inspect/configure/switch。

**Tech Stack:** Rust、Slint/Winit、首选 FemtoVG；Windows 固件 API/UAC，Linux efivarfs/pkexec/logind。具体依赖版本在任务 1 核对并锁定稳定版本。

**Spec:** [已批准设计](../specs/2026-09-08-boothop-design.md)。执行者必须先读完整规格；此计划不授权现在开始生产代码，也不授权真实固件写入或重启。

**生效修订：** [已用户批准的 opaque identity 修订](../specs/2026-09-09-opaque-identity-amendment.md)。本次只同步文档，不授权固件读取。下列精确组件及门槛替代初稿的非空OptionalData拒绝策略和正常更新配对MVP硬门槛。

**Linux-first调度修订：** [2026-09-10修订](../specs/2026-09-10-linux-first-amendment.md) 已获用户条件授权，以下分支同步待独立规格/质量审查通过后生效。审查前不实现；不再要求重复整体批准。所有实施项当前PENDING，Task1整体仍BLOCKED。

## Global Constraints

- MVP 支持 Windows 11，以及使用 systemd、具有可正常工作 polkit authentication agent 的 Linux 桌面。
- 不包含托盘、自启动、后台常驻、引导项创建或修复、BootOrder 修改、传统 BIOS 支持。
- 主界面明确显示“点击后将立即重启，请先保存工作”。按钮为“重启进入 Windows”或“重启进入 Linux”。
- 只有 GUI 包依赖 Slint；核心、平台代码和 helper 均不依赖 GUI 框架。
- 未知或较新的记录格式版本必须 fail closed。UnsupportedRecordVersion 与尚未配置是不同状态。
- 当前版本不能通过普通 configure 覆写不支持的记录，也不能把读取失败解释为记录不存在。MVP 不新增 reset 功能。
- Linux 首次使用时在 Linux 本地登记 Windows 启动目标；Windows 首次使用时在 Windows 本地登记 Linux 启动目标。一侧完成配置不会自动配置另一侧。
- 普通测试命令只能使用 mock/fake 平台接口，不能访问宿主 UEFI 或触发重启。
- 每次真实切换比较前后 BootOrder；永久顺序变化即失败，即使成功进入目标 OS。
- 重启请求已接受后不回滚。未知结果不等于拒绝。
- 普通启动 GUI 不主动提权；GUI 缓存不是 helper 的可信依据。
- 所有OptionalData（包括空）统一使用 `OpaqueExactV1 { algorithm: Sha256, byte_length: u64, digest: [u8; 32] }`；完整原始字节长度+SHA-256严格比较，不裁剪、重编码、删NUL/尾部或提取子集。未知二进制本身可登记，外层/设备路径/attributes规则不放宽。
- 任意identity失配均在BootNext与重启前停止，无SaveRecord、无自动configure；用户主动重新选择并确认OS后，经UAC/polkit登记新基线。未知记录/组件版本或算法是UnsupportedRecord，不可普通configure覆盖；损坏也不是Missing。
- 可信记录不含原始OptionalData，GUI缓存/普通日志同样禁止；指纹不默认公开。摘要依赖SHA-256抗碰撞假设，不证明内部语义、最终OS或启动链安全。

## Task 4：记录状态与 per-OS 配置规则

**Files:** 创建 `core/src/record.rs`、`core/tests/record.rs`；修改 `model/error/lib.rs`。

**Interfaces:** `decode_record(&[u8]) -> Result<TargetRecord, Error>`；`RecordState::{Missing,Ready(TargetRecord)}`，未知版本以 `Error::UnsupportedRecordVersion { found: u64 }` 返回，损坏以独立错误返回；`expected_target(host: Os) -> Os`。版本固定为本次已定义格式 1，不支持隐式降级迁移。
