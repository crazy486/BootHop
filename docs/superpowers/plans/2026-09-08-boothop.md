# BootHop Implementation Plan

> **For agentic workers:** REQUIRED SUB-SKILL: Use superpowers:subagent-driven-development (recommended) or superpowers:executing-plans to implement this plan task-by-task. Steps use checkbox (`- [ ]`) syntax for tracking.

**Goal:** 实现经过批准的 BootHop 小型双系统一次性切换工具，并提供隔离的自动化测试和显式验收流程。

**Architecture:** Rust core 统一解析、identity、业务状态和错误；平台层封装固件、受保护记录、授权及重启。普通权限 Slint GUI 仅发送意图，按需提权 helper 独立验证并执行 inspect/configure/switch。

**Tech Stack:** Rust、Slint/Winit、首选 FemtoVG；Windows 固件 API/UAC，Linux efivarfs/pkexec/logind。具体依赖版本在任务 1 核对并锁定稳定版本。

**Spec:** [已批准设计](../specs/2026-09-08-boothop-design.md)。执行者必须先读完整规格；此计划不授权现在开始生产代码，也不授权真实固件写入或重启。

**生效修订：** [已用户批准的 opaque identity 修订](../specs/2026-09-09-opaque-identity-amendment.md)。本次只同步文档，不授权固件读取。下列精确组件及门槛替代初稿的非空OptionalData拒绝策略和正常更新配对MVP硬门槛。

## Global Constraints

- MVP 支持 Windows 11，以及使用 systemd、具有可正常工作 polkit authentication agent 的 Linux 桌面。
- 不包含托盘、自启动、后台常驻、引导项创建或修复、BootOrder 修改、传统 BIOS 支持。
- 主界面明确显示“点击后将立即重启，请先保存工作”。按钮为“重启进入 Windows”或“重启进入 Linux”。
- 只有 GUI 包依赖 Slint；核心、平台代码和 helper 均不依赖 GUI 框架。
- 未知或较新的记录格式版本必须 fail closed。UnsupportedRecordVersion 与尚未配置是不同状态。
- 当前版本不能通过普通 configure 覆写不支持的记录，也不能把读取失败解释为记录不存在。MVP 不新增 reset 功能。
- Linux 首次使用时在 Linux 本地登记 Windows 启动目标；Windows 首次使用时在 Windows 本地登记 Linux 启动目标。一侧完成配置不会自动配置另一侧。
- 普通测试命令只能使用 mock/fake 平台接口，不能访问宿主 UEFI 或触发重启。
- 每次真实切换比较前后 BootOrder；永久顺序变化即失败，即使成功进入目标 OS。
- 重启请求已接受后不回滚。未知结果不等于拒绝。
- 普通启动 GUI 不主动提权；GUI 缓存不是 helper 的可信依据。
- 所有OptionalData（包括空）统一使用 `OpaqueExactV1 { algorithm: Sha256, byte_length: u64, digest: [u8; 32] }`；完整原始字节长度+SHA-256严格比较，不裁剪、重编码、删NUL/尾部或提取子集。未知二进制本身可登记，外层/设备路径/attributes规则不放宽。
- 任意identity失配均在BootNext与重启前停止，无SaveRecord、无自动configure；用户主动重新选择并确认OS后，经UAC/polkit登记新基线。未知记录/组件版本或算法是UnsupportedRecord，不可普通configure覆盖；损坏也不是Missing。
- 可信记录不含原始OptionalData，GUI缓存/普通日志同样禁止；指纹不默认公开。摘要依赖SHA-256抗碰撞假设，不证明内部语义、最终OS或启动链安全。

## 执行次序与研究门槛

任务 1 先完成只读证据收敛。任务 2–11 是后续实现任务，不在本次文档同步阶段执行。已取得Arch读取的Windows/Linux私有真实样本；公开fixture缺失不单独阻止MVP，普通CI仍使用synthetic。opaque exact策略已批准，但完整结构字段契约和Windows原生GetFirmwareEnvironmentVariableExW实际读取、权限、out attributes、payload与错误语义证据仍为Task1实施前硬门槛，当前BLOCKED。Arch副本不替代Windows证据；另获授权才可验证，无法安全观察的错误明确限制并以fake覆盖，不主动制造系统变化。不得编造样本或将模拟数据标为实机数据。

Windows/Arch自然更新配对与OptionalData内部解码不再是MVP strict exact-match硬门槛。配对仅用于未来放宽比较、归一化或降低误失效；任何结构化新宽松变换仍需格式依据和正反测试。真实BootNext写入/重启属于另行授权的后续验收。

没有外部原子比较写入保证时，本 MVP 的真实平台恢复结果为“不再写入，保留并报告可能残留”；值相等和 BootHop 内部锁不构成外部并发证明。不引入空泛的事务/插件框架来假装解决固件竞态。

实现任务按测试先失败、最小实现、测试通过、检查差异、提交执行；纯文档研究/同步不适用TDD，改用契约覆盖、JSON和差异检查。提交只暂存该任务文件；Git 作者缺失时不伪造身份、不修改全局配置，记录未提交原因并继续安全的本地工作。执行时才按适用技能处理 worktree；当前尚无生产实现。

## Task 5：核心 inspect/configure/switch 状态机

**Files:** 创建 `core/src/flow.rs`、`core/tests/flow.rs`、`core/tests/support/mod.rs`；修改 model/error/lib。

**Interfaces:** `Request::{Inspect,Configure{boot_id:BootId,os:Os},Switch{os:Os}}`；`execute(request: Request, host: Os, platform: &mut impl Platform) -> Result<Report, Error>`。

`Platform` 仅提供 `load_record() -> Result<RecordState,Error>`、`save_record(&TargetRecord) -> Result<(),Error>`、`read_options() -> Result<Vec<(BootId,LoadOption)>,Error>`、`read_next() -> Result<Option<BootId>,Error>`、`write_next(BootId) -> Result<(),Error>`、`reboot() -> RebootOutcome`、`check_environment() -> Result<(),Error>`。`RebootOutcome::{Accepted,Rejected,Unknown}`。没有 BootOrder 写入方法，也没有无条件清除方法。

`Report` 包含发现候选、记录状态诊断和 `Vec<Stage>`；`Stage::{TargetValidated,BootNextVerified,RebootAccepted,RebootRejected,RebootUnknown,ResidualPossible}`。保留平台原始错误码用于诊断，不伪造实际 OS 启动成功阶段。

- [ ] 对UnsupportedIdentityComponent重复上述三操作拒绝与无mutation断言；错误摘要长度/损坏记录也不得按Missing或自动恢复处理。
- [ ] 运行 `cargo test -p boothop-core --test flow`，确认失败；按请求分别实现读记录、共享验证、配置生成与切换。
- [ ] switch 在冲突时终止；已是目标时不写但仍重新读回并验证；新写后读回不一致不得 Reboot。写入前再次读取冲突状态，承认检查后仍可能有外部竞态。
